# 리디 독서노트 여러 권 가져오기

목표: `ridi_book_id` 속성이 있는 노트만 대상으로 여러 책을 수집하고, 전체 미리보기를 확인한 뒤 한 번에 반영한다.

## 구현 순서

1. 보관함의 Markdown을 읽고 속성이 있는 노트만 선별한다. 속성 값이 잘못됐거나 ID가 중복된 노트, 기존 밑줄 ID와 충돌하는 노트는 제외하고 이유를 표시한다. 속성이 없는 기존 노트는 제외한다.
2. 기존 인증된 로컬 연결을 여러 요청에 사용할 수 있도록 확장한다. 요청한 책 ID만 받고, 책별로 성공·오류·시간 초과를 기록한다. 취소와 종료 시 연결을 닫는다.
3. 브라우저 확장이 책별 페이지에서 기존 수집기를 순서대로 실행한다. 전체 개수가 확인되지 않은 결과는 실패로 처리한다. 다른 책의 데이터나 중복 응답은 수락하지 않는다.
4. 옵시디언에 책별 새 항목 수와 오류, 변경 내용을 표시한다. 사용자가 반영하기 전에는 파일을 쓰지 않는다.
5. 확인된 각 파일은 기존 `vault.process` 기반 검사를 사용하여 변경 여부와 ID를 다시 검증한다. 다른 파일의 실패가 이미 성공한 파일을 지우지 않도록 결과를 책별로 표시한다. 실패한 책은 재실행할 수 있고 기존 밑줄 ID로 중복을 막는다.
6. 스캔 및 중복·충돌·미리보기·취소·부분 실패·재실행을 자동 검사하고, 실제 브라우저와 옵시디언의 통합 흐름을 별도로 검증한다.

영향: 옵시디언 노트, 로컬 브라우저 연결, 리디 화면 수집. 다중 파일은 단일 트랜잭션이 아니므로 일부 파일만 저장될 수 있다. 오류 시 책별 상태를 표시하고, 기존 옵시디언 버전 기록을 복구 수단으로 사용한다.
